# 执行环境私有服务

应用通过一个已认证网关访问执行环境的私有 Agent。网关从不直接连接 Agent：
它把请求经由该环境所绑定的那一个 Runner Manager 的反向隧道流式转发。

```
应用 ──HTTPS──▶ 控制面 ──WebSocket──▶ Runner Manager ──HTTP──▶ 私有 Agent
                  │
                  └─ 按属主校验的围栏、有界请求、流式响应
```

## 端点

### `GET|POST|PUT|PATCH|DELETE|HEAD|OPTIONS /api/internal/execution-environments/{environment_id}/service/{path}`

把一个请求转发到该环境的私有 Agent。

必填：

- `Authorization: Bearer <application token>`——与其他内部路由相同的应用
  Bearer。这是该路径上唯一的身份来源。
- `X-Execution-Environment-Generation: <int64>`——调用方预期的代次围栏。
  它是围栏而不是身份：必须同时等于已存储的授权代次与已置备的容器代次。
- `Content-Length`——每个请求都必填。中继向 Agent 侧承诺逐字节精确的请求
  体，无法从推断出的长度得出这个承诺。

调用方从不指定目标。该路径上任何位置都没有 Manager ID、主机或端口参数，
查询串是不透明文本，绝不会被解析成地址。

| 状态 | 含义 |
| --- | --- |
| 200 | 转发的 Agent 状态与流式响应体。Server-Sent Events 与二进制响应体均增量转发。 |
| 400 | 不支持的方法，不可解析的路径/查询/请求头，或缺少 `Content-Length`。 |
| 401 | 没有应用 Bearer。 |
| 404 | 他人的或未知的环境，或 Agent 侧不存在的资源。他人的环境与未知环境无法区分。 |
| 409 | 围栏不匹配、环境未就绪，或中继无法接纳该流。 |
| 413 | 声明的请求体长度超过中继上限。 |
| 503 | 没有存活的 Manager 隧道，或隧道结束了该流。 |
| 504 | Agent 服务超时。 |

### `GET /api/internal/runner-manager/service-relay`

Manager 的隧道入口。

- 使用既有的 Runner Manager Bearer 认证。
- 要求 `df-env-http.v2` WebSocket 子协议；旧标签被拒绝。
- 每个 Manager 只允许一条存活隧道：第二次连接以 409 拒绝，且迟于断开
  退出的旧连接无法移除已取代它的隧道。
- 控制面每 15 秒探测一次隧道；静默 30 秒后关闭隧道，并让其承载的所有
  请求失败。

## 跨越中继的内容

请求：方法、有界的相对路径、不透明查询、精确的请求体，以及仅
`Content-Type` 与 `Accept`。调用方自身的 authorization、cookie、转发类
请求头与逐跳请求头都会被丢弃，绝不抵达 Agent。

响应：Agent 的状态、流式响应体，以及仅 `Content-Type`、`Cache-Control`、
`Retry-After`。转发的响应永远无法为调用方设置 cookie、把调用方重定向走，
或为其附加凭据。

## 上限

| 限制 | 取值 |
| --- | --- |
| 相对路径 | 1 KiB；不允许百分号转义、反斜杠、控制字符、空/`.`/`..` 段或带 authority 的形状 |
| 原始查询 | 8 KiB，不透明 |
| 单个转发请求头值 | 2 KiB |
| 请求或响应体 | 2 MiB |
| 控制帧 | 16 KiB |
| 传输消息 | 64 KiB |
| 数据帧载荷 | 32 KiB |

## 准入

1. 先校验应用 Bearer。
2. 读取并做有界检查代次围栏请求头。
3. 检查路径、查询、请求头与请求体长度。此时尚未触碰其他任何东西。
4. 读取一行按属主限定的数据，并对照它检查两处围栏。他人的环境与未知
   环境都不存在。
5. 把该流接纳到 Manager 的存活隧道。
6. **再次**读取该行，并重新检查该流的取消代次。
7. 只有到这一步才写出开启帧。

第 5、6 步封住了「停止或失效在调用方读取与隧道写入之间提交」这一竞态。
之所以重读数据库而不信任它，是因为内存中的注册表只是缓存，而非生命周期
的权威来源。

## 取消

已提交的 `stop` 或 `invalidate` 会取消该环境的存活流。被拒绝的变更不改变
任何东西，流继续运行。取消同时推进该环境的代次，因此与该变更竞态的注册
会被拒绝而不是被接纳。

在中途消失的客户端，其请求永远不会被当作完整请求报告给 Agent：在关闭
请求之前，声明长度与实际转发的字节数必须一致；请求体不足时取消而不是
标记完成。

## 并发

双向的每个控制帧都携带自己的流标识符（`df-env-http.v2`）：`open`、请求体、
`request_end`、`response_head`、响应数据、`end`、`error` 与 `cancel` 都通过读取帧
来关联，绝不依赖隧道的单例位置。一条隧道按标识符多路复用并发流——长连接
Server-Sent Events 与同时进行的 POST 并存——上限为每个环境 8 条、每个 Manager
32 条；请求体并行组装，响应在各自任务上服务。重用的标识符以带归属的固定错误
拒绝，未知或最近关闭的标识符被丢弃而不影响存活流，取消只移除其命名的流。
无论流以何种方式结束，配额恰好释放一次。

## Manager 侧

由 Manager 向外拨号；控制面从不向内拨号。配置了 `DESK_FOREMAN_URL` 后，
Manager 在既有上游拉取工作线程旁边持有一条已认证隧道（`df-env-http.v2`、
既有 Bearer 请求头），以有界退避重连，日志脱敏。没有 URL 或没有 Docker
后端时中继保持关闭，启动不受影响。

请求体按标识符并行组装：在环境互斥锁与文件预留之下，Manager 重查
持久屏障（已停止的代次绝不拨号）、属主标签与运行状态，从
`NetworkSettings.Networks[<受信任网络>]` 推导私有地址（仅私有 IPv4 或
唯一本地 IPv6；守护进程默认地址永远不算），读取该代次凭据，并注册粘性
取消接收器。两把锁在触碰网络之前释放，因此缓慢的 Agent 永远不会卡住
ensure 或 stop；中继也永远不会为了一次转发而自动 ensure 或 start。

Agent 跳只携带 `Content-Type`/`Accept`，外加由受信任用户名与存储令牌构成
的 Basic 认证。客户端不跟随重定向，也不读取环境代理。响应头限时 10 秒，
单条流至多存活 1 小时/128MiB，响应体增量流式传输（含 SSE），绝不整体缓冲。
已提交的 `stop` 在持久化停止代次后取消该环境的存活流（含容器已消失的分支）；
被取消的流报告其固定错误码，而不是合成的成功；诊断文本与令牌永远不上线。
