# 原生任务工作区目录

原生任务检出在其容器内只挂载到一个由任务工作区绑定推导出的目录：

```text
/workspace/bindings/<workspace_binding_id>
```

该路径是唯一共享定义：Manager 启动、容器复用与停止的挂载校验、同容器可写探测，以及
控制面任务描述符都使用它，四者因此不会各自漂移。绑定 id 以受限十进制数字呈现，
所以推导出的目录永远不会包含路径分隔符、上级目录段或宿主路径。

## 为什么每个绑定一个目录

检出位置是按工作区绑定保持稳定的标识。因此两个绑定绝不能共用同一位置，
而同一绑定的所有任务必须保持同一位置：

- 以相同 workspace key 登记的两个绑定仍是不同的，因为绑定 id 不同，即使呈现的工作区相同。
- 同一绑定的每个任务都解析到同一目录，使一个工作区在容器内对应一个固定位置，
  而不是每个任务一个位置。
- 任务 UUID 有意不参与路径。它随任务变化，会让每个任务看起来都位于不同位置。

**目录稳定只是位置稳定，不代表内容稳定。** 挂载到该位置的是归 Manager 所有的按任务检出目录
`<host-root>/<environment_uuid>/<task_uuid>/tree`，它由该任务自己的已封存种子生成。
因此同一绑定的后续任务会把不同的宿主源挂载到同一容器路径，并从自己的种子开始；
检出目录内不会继承任何内容。本次变更不改变检出生命周期，也没有实现共享或按工作区的工具缓存。

这是服务端自有的契约。它不复用任何 Agent 自身的项目身份，也不创建 Git 元数据：
共享种子协议会拒绝 `.git` 路径，因此原生检出不携带 Git 身份。

## 不包含的内容

- `/workspace` 本身只是根围栏。检出绝不会挂载到该根，持久状态卷必须与整个根互斥——
  位于 `/workspace` 之下的状态挂载仍按原规则被拒绝。
- 该目录是*规范性*路径，只说明 Manager 会把检出挂载到哪里；它不是任何容器正在运行的
  证明，也不包含 Manager 地址、镜像或凭据。
- 一切都不是调用方提供的。请求、描述符和挂载都不会接受宿主路径或任务目录，
  服务端始终从已存储的绑定 id 推导该值。

## 持久化边界

| 内容 | 位置 |
| --- | --- |
| 任务检出（种子文件、任务改动） | 归 Manager 所有的按任务宿主目录 `<host-root>/<environment_uuid>/<task_uuid>/tree`，在该单个任务存活期间绑定挂载到绑定目录，不会传入下一个任务。 |
| 需要跨任务存活的持久 Agent 状态 | 独立的持久状态卷，挂载到配置的状态挂载点，按环境隔离。持久状态应放在这里。 |
| 任务身份、标签、代次 | 环境标签与持久任务行；绝不编码进路径。 |

原生任务停止会保留该任务的检出与状态卷；释放任务仍是单独的显式操作。被保留的检出是按任务的
宿主目录，因此同一绑定的后续任务仍从自己的种子开始，而不是复用它。旧共享根布局下的既有检出
不会被迁移、别名化或清除：针对旧 `/workspace` 目标创建的容器只会通不过当前的配置匹配，
其启动或停止被拒绝，而不会被接管。
