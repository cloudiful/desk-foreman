# Application workspace tools

Application bearer tokens use `/api/internal/workspace-tools` with `X-DF-External-User-Id` and `X-DF-Workspace-Key`. Resource workspace requests additionally require `X-DF-Runner-Isolation: principal` and `X-DF-Lease-Owner` matching the external user identity; mutating requests must hold the applicable workspace lease. Identity and lease are never supplied in JSON. User and admin bearer tokens cannot use these routes. Each call re-resolves current application authority and workspace binding.

POST `shell` accepts `command`, optional `workdir` and optional `timeout_ms`; it returns an opaque `execution_id` and an initial output chunk. A failed dispatch can return an uncertain execution ID: retain it for reconciliation and do not automatically retry the start. POST `write-stdin` takes `execution_id` and nonempty `chars` and returns a descriptor without consuming output. POST `apply-patch`, `read`, `glob`, `grep` and `stat` use the documented workspace tool request schemas.

GET `executions/{execution_id}`, `/output` and `/final` return status, cursor-based output and final state respectively. POST `executions/{execution_id}/cancel` requests cancellation; terminal cancellation is idempotent. The final endpoint returns conflict while running. Output is encoded in `stdout_base64` and `stderr_base64`; decode base64 before interpreting bytes. Caps and counters are decoded-byte counts. `next_cursor` is opaque. `trimmed` indicates older retained bytes were evicted; `truncated` also indicates unread retained bytes remain after this chunk. `eof` requires terminal status, completed readers and delivery through both stream ends. Output can be unavailable after runner retention, returning conflict rather than an empty successful chunk.

Execution handles are in-memory and instance-local, not durable; restart or routing to another instance can lose them. After a manager restart, an old handle becomes uncertain or unavailable rather than addressing a replacement execution. Output cursors are bound to their execution and cannot be reused with another handle. Terminal handles expire after 900 seconds; runner output is retained for at most 300 seconds after confirmed completion and may be evicted earlier under capacity pressure. An unknown outcome is not success. The selected manager's per-owner session limit includes existing legacy sessions; its own concurrency gate also applies. The workspace write fence covers start, input and cancel dispatch, not the entire process lifetime.

Roll out a compatible runner-manager before or together with Desk Foreman; older managers do not support the retained-session jobs. This HTTP API is separate from the legacy MCP shell and its polling behavior.
